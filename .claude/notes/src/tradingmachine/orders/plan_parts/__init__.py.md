# src/tradingmachine/orders/plan_parts/__init__.py

The parts live in their own package rather than beside the fifty-four order modules, because they are not order types: none of them can be placed, and putting fifteen more modules in `tradingmachine.orders` would bury the order classes a reader is looking for. Each part has its own module and its own self-contained class, following the user's rule that similar cases are written out one by one rather than through a shared parameterised abstraction, which is also why `TimeAt`, `TimeAfter` and `TimeBefore` are three near-identical classes rather than one class taking a kind.

Every part has a `document()` method returning a dict with exactly one key, the part's UBI name. That one-key shape is what UBI's `PlanReader` requires for nodes, triggers, pricing values and presets alike, and `document()` is the name `OrderCandidate` and `ExposureWatch` already use for the same job. The shared base `PlanPart` exists only so that type annotations can say "any part" and so a forgotten override fails loudly.

Settings left as None are left out of the document, so UBI's own defaults apply, and a boolean that is False is left out too, since False is UBI's default for every boolean in the plan. `OrderPart` sends its one pricing rule inside a list because UBI's format takes a list, so that the modifiers `cap` and `discretion`, which UBI built on 2026-10-01, can be written beside the one rule that sets the price; UBI still refuses two rules that both set it, with the rule `two_setters`.

UBI writes the `fixed` pricing order type in capitals, `LIMIT` or `MARKET`, while the order template takes lower-case `limit` and `market`. The value is passed through unchanged, in keeping with sending UBI's vocabulary as plain strings, and the docstring of `FixedPricing` says so.

## The vocabulary brought up to UBI's, on 2026-10-02

The package began on 2026-10-01 with fifteen parts written against UBI's first three stages. By 2026-10-02 UBI had finished the plan, and an audit that day found every one of the fifteen still read correctly but the vocabulary far behind, so thirty-six parts were added, bringing the package to fifty-one: the joins `TogetherPart`, `SequencePart`, `RepeatPart` and `UsingPart`; the triggers `TimeFrom`, `CandleCloses`, `AccountCondition` and `LimitMarketable`; the pricings `PegPricing`, `ChasePricing`, `FollowInstrumentPricing`, `OptionModelPricing`, `StagesPricing` with `StageRule`, `FromFillPricing` and `FromParentFillPricing`; the modifiers `CapModifier` and `DiscretionModifier`; eleven executions; `PostOnlyGuard`; `Lifetime`; the venues `PreOpenVenue` and `PaperVenue`; and the quantities `PositionQuantity`, `ParentFillQuantity` and `ParentFillDeltaQuantity`. `TrailPricing` gained the average true range form and `NativeStopPricing` gained `exit_if_gapped`. Each class has a note of its own beside this one.

`OrderPart` takes each of UBI's list-valued slots as named arguments rather than as lists, and builds the lists itself. UBI's `pricing` list holds one price setter plus an optional `cap` and `discretion`, so `OrderPart` takes `pricing`, `cap` and `discretion` separately; this keeps "one pricing rule" visible in the signature and makes UBI's `two_setters` refusal hard to reach by accident. UBI's `execution` list holds one execution or an outer and an inner one, so `OrderPart` takes `execution` and `inner_execution`. `guards`, `lifetime` and `venue` are lists that UBI only ever reads one entry from, so `OrderPart` takes `guard`, `lifetime` and `venue` as single objects. An order's own instrument is given as an instrument object and sent as its `instrument_id`, as `PriceCrosses` already did.

Most parts still build a one-key document, the part's UBI name. `Lifetime`, `PreOpenVenue`, `PaperVenue` and `StageRule` are the exceptions, because UBI reads them as entries of a list with several keys rather than as named values, so their `document()` returns the entry itself. `PlanPart`'s docstring names them.

A boolean whose UBI default is True, such as a peg's `follows`, a together join's `group_margin` and a position quantity's `cancel_resting_first`, is taken as `bool | None` and sent only when it is not None, so that leaving it out keeps UBI's default; the rule that a False boolean is left out holds only for booleans whose default is False.
