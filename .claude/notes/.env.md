# .env and .env.example

Host-side connection settings for the data layer, consumed both by `utilities/configuration.py` and by `docker-compose.yml`.

The `*_HOST` and `*_PORT` values are the host-side view, meaning `localhost` plus the published port, because tradingmachine runs on the host while the databases run as containers. The same variables are read by `docker-compose.yml` to decide which host port to publish each service on.

There is deliberately no tier system in this project, so this single file is the whole configuration. The sibling projects carry `.env.dev`, `.env.uat`, and `.env.prod` alongside per-tier port bands; none of that applies here.

`.env.example` is mechanically derived from `.env` by blanking every value, so the two never drift in which keys they list.

## Credentials

The password is shared across Redis, MongoDB, and Postgres, which was the user's explicit choice. Chroma takes none, because it has had no server-side authentication since version 1.0.0.

`.env` is listed in `.gitignore`, and the containers bind to `127.0.0.1` only, so the password is not reachable from off-box.

## Chroma has no username or password keys

Unlike the sibling projects, which carry `*_CHROMADB_USERNAME` and `*_CHROMADB_PASSWORD` keys that can only ever be empty, those keys are omitted here.
